1. 总览：三层 + 支撑

项目在架构上明确分为 3 层（Layer 1 / 2 / 3）， 另有 RAG、参数经验库、MATLAB 仿真引擎等横切支撑，它们不是独立业务层，而为三层服务。

2. Layer 1 — 任务输入与总控

入口：cli_agent.py

作用：整个系统的「大脑」和主循环，不直接实现制导算法，只负责编排。

职责说明
解析任务 从自然语言 / prompt.txt 解析工况（如 RUN_CASE='T'; SUB_IDX=4）和五项指标（命中率、SEP、PeakNy、PM、BW）
初始化组件 LLM、RAG、Hermes、RL 优化器、Layer3 工作流、参数经验库
驱动外层迭代 max_iterations（默认 4）轮「规划 → 生成 → 优化 → 反思」
层间衔接 把 Layer3 的 suggestion、next_action 喂回下一轮 Layer2；进 Layer3 前跑 Layer2 Gate 与 _rule_check 指标复核
收尾 经验回写、模型保存、生成报告（Step 4 / 5）

日志关键字：[Step 1]、Iteration N/M、Feeding back to Layer 2

3. Layer 2 — Hermes 内容生成与仿真

入口：hermes_integration.py + multi_agent/tools/ 工具链

作用：用 LLM + 工具生成/修改 MATLAB 脚本并跑蒙特卡洛仿真，不做 PPO 参数搜索。

子步骤核心模块做什么
Step 2 规划 IntelligentTaskPlanner RAG 检索、对比历史指标，选 TUNE_PARAMS / MODIFY_LAW / REUSE_HISTORY
Step 2.5 生成 generate_matlab 基于 monte_carlo_single.m 生成或修改脚本（改参数 or 改 gf() 制导律）
语法/兼容 syntax_check_matlab、verify_guidance_compat 校正语法、检查制导律数学适配性
仿真 run_simulation 跑 N_MC 次蒙特卡洛，得到 hit / SEP / PeakNy / PM / BW
判定 judge_requirements 规则 + LLM 判断五项指标；PeakNy 以 peak_ny_max 为准；cli 进 Layer3 前再复核
Layer2 Gate layer2_script_gate syntax/smoke → T4 MODIFY 闭环快扫；失败时 near-miss 可同轮切 TUNE_PARAMS

两条出口

  • satisfied=True → 跳过 Layer3 的 RL，直接反思 + 写经验
  • satisfied=False → 把 script_path + initial_metrics 交给 Layer3

Layer2 不包含 PPO / Expert 工具，避免 Hermes 与 RL 混在一起。

4. Layer 3 — 优化工作流

入口：optimization_workflow.py

作用：在 Layer2 给出的脚本和初值上，系统搜索驾驶仪 9 维参数（w1,zeta1,tao1,w2,zeta2,tao2,w3,zeta3,N_pn），直到达标或给出下一轮建议。

阶段模块做什么
策略选择 _select_strategy + t4_low_risk Expert 或 PPO；T4 post-MODIFY 强制 Expert；4/5 仅 peak 时可跳过搜参
初值注入 resolve_initial_auto_params T4 / post-MODIFY 使用保守 w、N_pn 并 clamp 至上限
MODIFY 失败门控 should_block_tune_after_bad_modify peak>30g 或 hit<85% 时返回 next_action=modify_law，禁止 TUNE
Expert _run_expert_tuning 最多 5 轮：LLM 建议参数 → 仿真 → 评估
PPO MatlabRLOptimizer 每 episode 跑 N_MC 次 MC，PPO 更新策略
CLS constraint_local_search PPO 后在约束邻域做局部精修
反思 ReflectionAgent + design_path_policy 分析是否达标；输出 next_action 和优化建议
判断 JudgmentAgent 规则检查指标；辅助 Expert/PPO 早停

两条出口

  • 五项全达标 → 写 ParameterExperience、生成报告，status=done
  • 未达标 → status=needs_iteration，next_action=tune_params 或 modify_law → 回到 Layer1 下一轮

5. 层与层之间如何联系

一次完整迭代的数据流：

用户 prompt
    ↓
[Layer 1] 解析工况 + 启动第 N 轮迭代
    ↓
[Layer 2] Planner → mode=TUNE_PARAMS / MODIFY_LAW
    ↓
[Layer 2] Hermes: generate_matlab → run_simulation → judge_requirements
    ↓  cli: _rule_check(hermes_sim_metrics)
[Layer 2 Gate] ensure_script_ready_for_layer3 (smoke + MODIFY 闭环)
    ↓  near-miss? → task_mode=TUNE_PARAMS（同轮）| blocked → 下轮 MODIFY
[Layer 3] OptimizationWorkflow (Expert / PPO / CLS / Reflection)
    ↓  best_params, best_metrics, next_action, suggestion
[Layer 1] 写入 _optim_history，若未达标且 iteration < max_iterations
    ↓
回到 [Layer 2]（带上 prev_suggestion、next_action、历史指标）

关键传递物

从 → 到传递内容
L1 → L2 current_prompt、上一轮 suggestion、task_mode（可强制 MODIFY_LAW）
L2 → L3 .m 脚本路径、initial_metrics、mission_conditions、是否 directly_satisfied
L3 → L1 best_params、best_metrics、next_action、suggestion、rl_hyperparams
L1 → L2（下轮） _optim_history、_prev_rl_best_params、_forced_next_action
一句话：L1 总控迭代 → L2 生成脚本并仿真判指标 → L3 自动调参并反思 → L3 建议回到 L1 → L1 驱动下一轮 L2（改参或改制导律）。

10. 与纯 TUNE_PARAMS 路径的区别

flowchart LR A[T4 Layer2 仿真] --> B{PeakNy_max ≤ 20g?} B -->|是，5/5| C[Layer3 跳过 RL
直接反思写经验] B -->|否，其余达标| D[Layer3 跳过 Expert/PPO
next_action=modify_law] B -->|否，多项不达标| E[Layer3 Expert/PPO
先 TUNE_PARAMS] D --> F[Iter2 MODIFY_LAW
改 gf] F --> G[Layer3 在新律上调参] G --> H{5/5?} H -->|否，差一点点| I[Iter3~4 tune_params] H -->|是| C

T4 的典型瓶颈是 PeakNy_max，因此在当前策略下， 多数会先 TUNE 摸底 → 发现 4/5 → MODIFY_LAW（T4 用内置克制 APN）→ Expert 小步调参收尾， 而不是在纯 PN 律上直接 PPO 100 ep，或让 LLM 自由写激进 APN。

11. T4 低风险与 Gate 策略（v0.4.1）

配置：config.yaml → t4_low_risk + simulation；实现：t4_low_risk.py、layer2_script_gate.py

规则实现
T4 识别RUN_CASE='T' + SUB_IDX=4，或 prompt 含 T4/工况4
4/5 仅 PeakNy_max 超标Planner / Reflection / design_path → MODIFY_LAW
确定性 gf()GF_APN_T4_MINIMAL：PN + 0.45 前馈 + 低通 + t_go 关断 + tanh/clip 20g
Layer2 Gate 闭环MODIFY 后以 modify_gate_nmc（默认 10）快扫；modify_gate_peak_g=30 为 Gate 上限
near-miss TUNEshould_gate_near_miss_tune：20g<max≤30g 且 hit/SEP OK → 同轮 TUNE_PARAMS 进 Layer3
MODIFY 灾难失败peak>30g 或 hit<85% → should_block_tune_after_bad_modify 禁止 TUNE
post-MODIFY Layer3should_force_expert_after_modify；episode 上限 50
判定口径任务验收与 RL 奖励看 peak_ny_max；cli _rule_check 与 Gate metrics 为可信来源
两层 Peak 阈值：任务指标 PeakNy≤20g；Gate 闭环允许到 30g 才硬拦——介于二者之间且其余指标 OK 时走 near-miss TUNE，避免在已可用律上空转 MODIFY。

12. 指标可信链（judge / cli / Gate）

历史上曾出现 Hermes judge_requirements 手填指标（如 SEP=4.01）与 stdout 解析（SEP=9.13m）不一致，导致误跳过 RL。v0.4.1 采用多层校验：

环节数据来源作用
run_simulationparse_sim_stdout → last_metrics仿真 stdout 解析为权威数值
judge_requirementsLLM 传入 metrics + 规则层快速判 satisfied；硬约束失败时 LLM 不可翻案
cli_agenthermes_sim_metrics进 Layer3 前 _rule_check 复核；纠正误跳过 RL
Layer2 Gatesmoke / MODIFY 闭环重跑更新 hermes_sim_metrics；闭环 PeakNy 决定是否 BLOCK 或 near-miss
optimization_workflowconstraints_satisfied反思后终态再校验；未全过则不标 done

日志对照：Hermes 侧 [Hermes sim metrics] 与 cli [Layer2→3] Rule-check、[Layer 2 Gate] 应使用同一套解析字段（含 PeakNy_max）。

13. 术语速查

术语含义（本项目语境）
PN比例导引：法向加速度 ∝ 视线角速率 × N × Vc；模板默认 gf() 结构
APN增广比例导引：PN + 目标机动补偿（a_T_perp 前馈）；T4 低风险模板含 0.45 增益
gf()MATLAB 制导律函数，输出过载指令 N1/N2；MODIFY_LAW 改此函数
cf()驾驶仪函数，跟踪 N1/N2；TUNE_PARAMS 主要调 w1…N_pn
PeakNy_max蒙特卡洛各样本过载的最大值；安全硬约束看此项
4/5五项指标中四项达标、一项未达标；T4 常见为仅 peak 超标
MODIFY_LAW修改 gf() 算法结构（非单纯改参数值）
TUNE_PARAMS在固定 gf 结构下优化驾驶仪 9 维参数
Layer2 Gate进 Layer3 前 syntax/smoke + T4 MODIFY 闭环 PeakNy 校验；配置 modify_gate_peak_g
near-missGate 因 peak 拦截但 20–30g 且 hit/SEP OK → 同轮 TUNE 而非继续 MODIFY
ExpertLayer3 LLM 引导小步调参；T4 post-MODIFY 首轮强制使用
