## 改进 1：奖励函数自适应优化

### 问题

原始奖励函数对 PeakNy 的惩罚是**线性的**：

```python
# 原始（线性惩罚）
penalty = peak_ny_penalty * min(overshoot, 2.0)
```

这导致：
- 轻微超标（如 21g）：惩罚很小，RL 不够重视
- 严重超标（如 30g）：惩罚很大，但已经太晚了

### 解决方案

实现**自适应惩罚**，根据超标严重程度动态调整惩罚强度：

```python
# 改进（自适应惩罚）
if overshoot < 0.2:      # 轻微超标（<20%）
    penalty_scale = 1.0  # 基础惩罚
elif overshoot < 0.5:    # 中等超标（20-50%）
    penalty_scale = 1.5  # 1.5 倍惩罚
else:                     # 严重超标（>50%）
    penalty_scale = 2.5  # 2.5 倍惩罚

penalty = peak_ny_penalty * penalty_scale * min(overshoot, 2.0)
```

### 效果

| 超标程度 | 原始惩罚 | 改进后惩罚 | 改善 |
|---------|---------|----------|------|
| 轻微（21g） | 0.125 | 0.125 | 无变化 |
| 中等（25g） | 0.313 | 0.469 | **+50%** |
| 严重（30g） | 0.625 | 1.563 | **+150%** |

**关键优势**：
- RL 更早发现 PeakNy 超标问题
- 对中等超标更敏感，避免恶化
- 对严重超标施加强有力的惩罚

## 改进 2：PPO 学习参数优化

### 问题

原始参数导致 PPO 收敛速度慢：

```yaml
# 原始
lr_actor: 0.0003
lr_critic: 0.001
episodes_per_update: 5
```

这导致：
- 策略更新不够频繁
- 学习速度慢
- 需要更多 episode 才能收敛

### 解决方案

优化三个关键参数：

```yaml
# 改进
lr_actor: 0.0005          # 从 0.0003 → 0.0005（+67%）
lr_critic: 0.002          # 从 0.001 → 0.002（+100%）
episodes_per_update: 3    # 从 5 → 3（更频繁更新）
```

### 效果

| 参数 | 原始 | 改进 | 效果 |
|------|------|------|------|
| **lr_actor** | 0.0003 | 0.0005 | 学习速度 ↑ 67% |
| **lr_critic** | 0.001 | 0.002 | 价值估计 ↑ 100% |
| **episodes_per_update** | 5 | 3 | 更新频率 ↑ 67% |

**关键优势**：
- Actor 网络学习更快
- Critic 网络更准确估计价值
- 策略更新更频繁，反馈更及时
- 预期收敛速度提升 **30-50%**

### 数学原理

PPO 的策略梯度：

```
∇J = E[∇log π(a|s) * A(s,a)]

其中：
- 学习率越高 → 梯度步长越大 → 收敛越快
- 更新越频繁 → 反馈循环越短 → 学习越有效
```

## 技术细节

### 1. 自适应惩罚的数学原理

```
标准惩罚：P = w * overshoot
自适应惩罚：P = w * scale(overshoot) * overshoot

其中 scale(overshoot) 是分段函数：
  - overshoot < 0.2: scale = 1.0
  - 0.2 ≤ overshoot < 0.5: scale = 1.5
  - overshoot ≥ 0.5: scale = 2.5

效果：在超标早期就施加强有力的惩罚，防止恶化
```

### 2. PPO 学习速度的影响

```
策略梯度更新：θ ← θ + α * ∇J

其中：
- α（学习率）越大 → 单步改进越大 → 收敛越快
- 更新频率越高 → 反馈循环越短 → 学习越有效

改进后：
- lr_actor 增加 67% → 单步改进 ↑
- lr_critic 增加 100% → 价值估计 ↑
- 更新频率增加 67% → 反馈循环 ↓
```

### 3. AMRO 跳变检测的灵敏度

```
跳变判定：梯度 > threshold AND 参数变化 < 0.3

原始：threshold = 0.5（保守）
改进：threshold = 0.4（敏感）

效果：更容易检测到跳变，更早避免低效区域
```

## 风险与缓解

### 风险 1：学习率过高导致不稳定

**风险**：更高的学习率可能导致策略振荡
**缓解**：
- 保持 clip_ratio = 0.2（PPO 裁剪系数）
- 监控 actor_loss 和 critic_loss
- 如果不稳定，降低学习率

### 风险 2：AMRO 误报导致禁区过多

**风险**：过敏感的跳变检测可能标记不必要的禁区
**缓解**：
- 监控 AMRO 统计信息
- 如果禁区过多（>5），提高 gradient_threshold
- 如果禁区太少（<2），降低 gradient_threshold

### 风险 3：更频繁的更新导致过拟合

**风险**：过频繁的策略更新可能过拟合当前 batch
**缓解**：
- 保持足够的 batch 大小（episodes_per_update = 3）
- 使用 advantage 归一化
- 监控价值函数误差
