# T4工况：窄可行域问题完整解决方案

## 问题陈述

T4工况存在**"接近可行"的区域，但比T1-T3窄得多，也更容易被PPO探索冲坏**。

```
现象：
├─ T1-T3：RL快速收敛（30-50 episode）
├─ T4：RL无法收敛（100+ episode仍在振荡）
└─ 原因：T4的可行域太窄，PPO的标准探索策略容易"冲坏"

根本原因：
├─ 高频机动的物理约束导致可行域狭窄
├─ 参数空间梯度陡峭（小参数变化 → 大指标变化）
├─ PPO的大步长探索容易越过可行域边界
└─ 一旦越过边界，奖励崖式下降，无法恢复
```

## 解决方案

### 方案1：梯度陡峭检测与自适应探索 ⭐⭐⭐ 最推荐

**核心思想**：自动检测梯度陡峭区域，动态降低探索幅度

**工作原理**：
```
梯度 = 奖励变化 / 参数变化

高梯度（>2.0）→ 梯度陡峭 → 降低探索幅度（×0.5）
低梯度（<2.0）→ 梯度正常 → 标准探索幅度
```

**实施**：

- 修改 `optimize()` 方法（约20行）
- 总计：约50行代码

- ✅ T4在50-100 episode内收敛
- ✅ 自动识别窄可行域
- ✅ 避免PPO大步长冲坏可行域

**实施时间**：1-2小时

**详细指南**：见 `STEEP_GRADIENT_FIX.md`

### 方案2：奖励崖式检测与回退 ⭐⭐⭐ 推荐

**核心思想**：检测到掉入奖励崖时，自动回退到上一个好的参数

**工作原理**：
```
监测奖励变化：
├─ 奖励正常下降 → 继续探索
├─ 奖励崖式下降（>3倍） → 检测到奖励崖
└─ 回退到安全参数 + 小扰动 → 继续探索
```

**预期效果**：

## 技术细节

### 为什么T4的可行域更窄？

1. **高频机动的物理约束**
   - 高频响应要求：w1, zeta1必须在很窄的范围内
   - 过高：过载爆炸（PeakNy > 50g）
   - 过低：无法跟踪目标（命中率下降）
   - 可行范围：可能只有全范围的10-20%

2. **多目标冲突**
   - PeakNy和PM的目标冲突
   - 降低PeakNy → PM升高
   - 降低PM → PeakNy升高
   - 可行域是这两个约束的交集（更窄）

3. **梯度陡峭**
   - 参数变化小 → 指标变化大
   - 容易越过可行域边界
   - 一旦越过，奖励崖式下降

### 梯度陡峭的数学定义

```
梯度 = Δ奖励 / Δ参数

高梯度（>2.0）：
├─ 参数变化小 → 奖励变化大
├─ 说明参数空间陡峭
└─ 容易越过可行域边界

低梯度（<2.0）：
├─ 参数变化大 → 奖励变化小
├─ 说明参数空间平缓
└─ 容易找到可行参数
```

### 自适应探索衰减的原理

```
标准PPO探索衰减：
exploration_std = base_std × (1 - episode / max_episodes)

自适应探索衰减：
if 梯度陡峭:
    exploration_std = base_std × (1 - episode / max_episodes) × 0.5
else:
    exploration_std = base_std × (1 - episode / max_episodes)

效果：
├─ 梯度陡峭时：小步长探索，精细搜索
└─ 梯度正常时：大步长探索，快速收敛
```
