# Layer 2 Gate 闭环快扫失败分析

## 问题描述

运行系统时出现错误：

```
[Layer 2 Gate] Validating script before Layer 3 (smoke nmc=5)…
2026-06-09 20:12:55 - [PhysicsBounds] OK peak_cmd_g=20.00g pass=True
2026-06-09 20:12:55 - [Layer2Gate] T4 MODIFY closed-loop gate nmc=10
[Layer 2 Gate] ✗ BLOCKED Layer 3 — MODIFY 闭环快扫 PeakNy_max=48.3g>30g，拒绝进入 Layer3
RL optimisation did not produce a valid result; nothing written.
```

## 核心问题

### 两层验证的矛盾

```
Layer 2 Gate 有两层验证：

1. 物理限幅探测 (Physics Bounds)
   ├─ 测试内容：gf() 函数在极端工况下的输出
   ├─ 限制条件：peak_cmd_g ≤ 20g
   ├─ 结果：✅ 通过 (peak_cmd_g=20.00g)
   └─ 说明：制导律函数本身没问题

2. 闭环快扫 (Closed-Loop Quick Scan)
   ├─ 测试内容：完整的制导+驾驶仪闭环系统
   ├─ 限制条件：PeakNy_max ≤ 30g
   ├─ 结果：❌ 失败 (PeakNy_max=48.3g)
   └─ 说明：闭环系统性能不满足要求
```

### 为什么会出现矛盾？

```
物理限幅探测 vs 闭环快扫：

物理限幅探测：
  - 只测试 gf() 函数的输出
  - 输入：极端工况 (Tx, Ty, Tz, V, 姿态等)
  - 输出：N1, N2 命令
  - 限制：peak_cmd_g ≤ 20g
  - 结果：✅ 通过

闭环快扫：
  - 测试完整的闭环系统
  - 输入：任务工况 (T4 mission)
  - 处理链：制导律 → 驾驶仪 → 动力学 → 过载
  - 输出：PeakNy (实际过载)
  - 限制：PeakNy_max ≤ 30g
  - 结果：❌ 失败 (48.3g)

原因：
  - 制导律输出 (20g) 经过驾驶仪放大
  - 驾驶仪增益可能很高
  - 导致实际过载 (48.3g) 远超制导律输出 (20g)
```

## 根本原因分析

### 问题链条

```
1. Hermes 生成 MODIFY_LAW 脚本
   ├─ 修改制导律代码
   └─ 保持驾驶仪参数不变
   ↓
2. 物理限幅探测
   ├─ 测试 gf() 函数输出
   ├─ 限制：peak_cmd_g ≤ 20g
   └─ 结果：✅ 通过 (20.00g)
   ↓
3. 闭环快扫 (nmc=10)
   ├─ 测试完整闭环系统
   ├─ 制导律输出 → 驾驶仪处理 → 动力学 → 过载
   ├─ 限制：PeakNy_max ≤ 30g
   └─ 结果：❌ 失败 (48.3g)
   ↓
4. Layer 2 Gate 阻止 Layer 3
   ├─ 原因：PeakNy_max=48.3g > 30g
   └─ 结果：RL 优化被阻止
   ↓
5. 优化失败
```

### 为什么制导律输出 (20g) 会变成过载 (48.3g)？

```
可能的原因：

1. 驾驶仪增益过高
   ├─ 制导律输出：20g
   ├─ 驾驶仪增益：2.4x
   └─ 实际过载：48.3g ✓ (20 × 2.4 ≈ 48)

2. 驾驶仪参数不匹配
   ├─ w1, zeta1, tao1 不适合新的制导律
   ├─ 导致过度响应
   └─ 实际过载超标

3. 制导律与驾驶仪不兼容
   ├─ 制导律设计假设驾驶仪带宽为 X
   ├─ 实际驾驶仪带宽为 Y (Y > X)
   ├─ 导致过度跟踪
   └─ 实际过载超标

4. 闭环系统不稳定
   ├─ 制导律 + 驾驶仪形成不稳定的闭环
   ├─ 导致振荡和过冲
   └─ 实际过载超标
```

## 配置分析

```yaml
t4_low_risk:
  enabled: true
  deterministic_apn: true
  ny_limit_g: 20.0
  max_n_pn: 4.5
  modify_gate_peak_g: 30.0           # ← 物理限幅探测限制
  modify_gate_hit_min_pct: 85.0
  modify_fail_peak_g: 30.0           # ← 闭环快扫限制
  modify_fail_hit_rate_min: 85.0

  post_modify_max_episodes: 50
  post_modify_ppo_max_episodes: 40
```

### 关键参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `modify_gate_peak_g` | 30.0g | 物理限幅探测限制（gf() 输出） |
| `modify_fail_peak_g` | 30.0g | 闭环快扫限制（实际过载） |
| `modify_gate_nmc` | 10 | 闭环快扫仿真次数 |

### 问题

```
当前配置：
  - 物理限幅探测限制：30.0g
  - 闭环快扫限制：30.0g
  - 实际过载：48.3g

问题：
  - 制导律输出 (20g) 通过物理限幅探测
  - 但闭环过载 (48.3g) 远超闭环快扫限制 (30.0g)
  - 说明驾驶仪增益过高或参数不匹配
```

## 解决方案

### 方案1：降低物理限幅探测限制（推荐）

**修改**：`config.yaml` 第525行

```yaml
t4_low_risk:
  modify_gate_peak_g: 15.0  # ← 从 30.0 改为 15.0
```

**理由**：
- 物理限幅探测限制应该更严格
- 给驾驶仪增益留出安全余地
- 如果 gf() 输出 ≤ 15g，驾驶仪即使增益 2x，也只有 30g

**效果**：
- ✅ 更严格的前置检查
- ✅ 减少闭环快扫失败
- ✅ 提高优化成功率

### 方案2：降低闭环快扫限制（保守）

**修改**：`config.yaml` 第527行

```yaml
t4_low_risk:
  modify_fail_peak_g: 40.0  # ← 从 30.0 改为 40.0
```

**理由**：
- 允许更高的过载
- 给驾驶仪更多的响应空间

**效果**：
- ✅ 减少闭环快扫失败
- ❌ 可能允许不安全的过载
- ❌ 不推荐

### 方案3：调整驾驶仪参数（最优）

**修改**：驾驶仪参数 (w1, zeta1, tao1)

```matlab
% 降低驾驶仪增益
w1 = 30.0;      % ← 从 40 改为 30 (降低自然频率)
zeta1 = 0.8;    % ← 从 0.7 改为 0.8 (增加阻尼)
tao1 = 0.15;    % ← 从 0.1 改为 0.15 (增加时间常数)
```

**理由**：
- 降低驾驶仪响应速度
- 减少过冲
- 更好地匹配新的制导律

**效果**：
- ✅ 最优解决方案
- ✅ 系统更稳定
- ✅ 性能更好

### 方案4：混合方案（最实用）

**步骤1**：降低物理限幅探测限制

```yaml
modify_gate_peak_g: 15.0  # 从 30 改为 15
```

**步骤2**：增加闭环快扫仿真次数

```yaml
modify_gate_nmc: 15  # 从 10 改为 15
```

**步骤3**：监控闭环快扫结果

```python
if pny > 30.0:
    logger.warning(
        "[Layer2Gate] PeakNy_max=%.1fg close to limit (30g) — "
        "consider tuning autopilot parameters",
        pny
    )
```

**效果**：
- ✅ 更严格的前置检查
- ✅ 更充分的仿真验证
- ✅ 更好的监控
