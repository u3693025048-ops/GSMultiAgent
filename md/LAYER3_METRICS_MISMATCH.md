## 问题描述

```

PM=69.2° 
BW=88.6r/s
```

```
命中率: 96.0% ↑
SEP: 4.09m ↓
PeakNy: 19.60g ↓↓
```

## 根本原因分析

### 可能的原因

```
1. 报告中的"仿真指标"来自不同的脚本版本
   - Layer 3 使用的脚本：guidance_simulation_T4_modlaw_1781109633.m
   - 报告中的指标可能来自：修改后的脚本版本
   - 结果：制导律实现不同，指标不同

2. 报告中的"仿真指标"来自不同的参数设置
   - Layer 3 使用的参数：w1=45, w2=45, w3=45, N_pn=4.0
   - 报告中的指标可能使用：不同的参数设置
   - 结果：参数不同，指标不同

3. 报告中的"仿真指标"来自不同的工况
   - Layer 3 运行：RUN_CASE='T', SUB_IDX=4
   - 报告中的指标可能来自：不同的工况
   - 结果：工况不同，指标不同

4. 报告生成时的数据混淆
   - 报告中混淆了不同阶段的数据
   - Layer 2 的结果 vs Layer 3 的结果
   - 结果：数据来源不清楚
```

## 问题诊断

### 问题1：报告中的数据不一致

报告中出现了两组看似相同但实际不同的数据：
- 第121-131行：SEP=11.32m, PeakNy=22.5g
- 第158-167行：SEP=11.32m, PeakNy=22.52g

这两组数据实际上是同一组数据，只是精度不同。

### 问题2：用户提到的数据来源不明

用户提到的数据（SEP=4.09m, PeakNy=19.60g）与报告中的数据不一致，可能来自：
- 不同的报告
- 不同的脚本版本
- 不同的参数设置

## 解决方案

### 方案1：确认数据来源

**步骤**：
1. 查看用户提到的"仿真指标"来自哪个报告
2. 确认是否来自之前的运行
3. 确认是否来自不同的脚本版本

### 方案2：统一报告中的数据

**改进**：
- 在报告中明确标注数据来源
- 说明每组数据对应的脚本版本
- 说明每组数据对应的参数设置

### 方案3：改进报告生成逻辑

**建议**：
- 只保留最终的仿真结果
- 避免混淆不同阶段的数据
- 明确标注数据来源和时间戳
